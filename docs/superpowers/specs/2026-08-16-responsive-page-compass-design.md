# 响应式页面罗盘与章节导航设计

日期：2026-08-16  
范围：全站共享 `PageCompass`、滚动进度逻辑与相关响应式样式

## 目标

在不修改现有文字、页面内容、URL、章节 ID 或部署方式的前提下，把右侧页面罗盘打磨成一个稳定的阅读定位工具：百分比、当前章节和 `01/02/03` 章节入口由同一套状态驱动，并在桌面、平板、移动端、触控设备、键盘和 reduced-motion 环境下保持可理解、可操作和不遮挡内容。

版本更新继续只直接提交到 `main`，不新建分支，不创建 PR；`dist/` 只能由构建生成，不能手工修改。

## 当前问题与设计判断

- `PageCompass.vue` 同时承担章节观察、滚动方向判断、移动端显隐、焦点恢复和渲染，状态边界较多，后续调整容易产生互相覆盖。
- 页面进度和章节活动状态分别计算，快速滚动、动态内容高度、地址栏伸缩或横竖屏切换时可能出现短暂不同步。
- 桌面端的 `01/02/03` 是有效链接，但视觉上更像标记；当前项、章节名称和上一/下一章之间的层级仍可更明确。
- 移动端已经有底部浮动结构，但需要更系统地处理安全区、窄屏压缩、触控尺寸、焦点可见性和滚动方向状态。

设计判断：`01/02/03` 保留为可点击的章节导航，不改为装饰性编号；罗盘的签名元素是“编辑档案中的阅读仪表”，强调定位和节奏，而不是增加新的视觉内容。

## 方案与选型

采用响应式阅读仪表盘方案：

1. 抽离可测试的页面罗盘状态逻辑，集中管理当前章节、进度、滚动方向、移动端显隐和 viewport 变化。
2. 保持 `PageCompass.vue` 作为展示与事件绑定组件，继续从 `pageRegistry` 接收章节数据。
3. 通过语义 token 和明确的桌面/平板/移动断点控制几何尺寸，避免用 JS 判断设备类型来决定布局。

仅调整 CSS 的方案无法稳定处理状态同步；复杂底部抽屉或手势方案会增加移动端干扰，因此不采用。

## 组件与数据流

### `usePageCompass`

新增一个共享 composable，输入为只读章节列表，输出以下状态与动作：

- `progress`：`0` 到 `1` 的页面阅读进度。
- `percent`：用于显示和 ARIA 的四舍五入百分比。
- `activeIndex`、`activeSection`、`previousSection`、`nextSection`：当前章节导航状态。
- `mobileState`：`quiet`、`reading` 或 `visible`。
- `isMobileViewport`、`isVisible`：响应式 viewport 和罗盘可见状态。
- `selectSection(id)`、`goTop()`：章节选择与返回顶部动作。

该 composable 只依赖浏览器滚动、`IntersectionObserver`、`matchMedia` 和必要的尺寸观察；不修改内容数据，也不持有页面文案。

### 状态优先级

1. 焦点在罗盘内部时，罗盘保持可见，不能因为滚动方向被收起。
2. 桌面端和平板端罗盘始终可见，只改变视觉状态，不改变可操作性。
3. 移动端顶部位置保持 `quiet`；向下阅读进入 `reading` 并短暂收起；向上阅读、滚动停止、章节跳转或获得焦点后进入 `visible`。
4. `prefers-reduced-motion: reduce` 只取消位移和渐变动画，不改变显隐语义、焦点顺序或内容。

### 活动章节判定

- 优先使用 IntersectionObserver 观察注册章节。
- 多个章节同时进入观察区域时，按距离阅读锚点最近的章节选择，而不是依赖 entries 返回顺序。
- hash 初始定位和点击章节后立即更新活动章节；观察器随后负责与真实滚动位置重新同步。
- 章节缺失或页面高度不足时保持安全默认值，不抛出运行时错误。

## 响应式视觉与交互

### 桌面端（大于 1024px）

- 罗盘固定在视口右侧，避开主体最大宽度和浏览器边缘。
- 百分比圆环是视觉锚点和返回顶部按钮；圆环内部同时保留箭头与百分比。
- 当前章节区显示 `01 / 03` 与短章节名。
- 章节列表显示编号和活动圆点；悬浮或键盘聚焦时在左侧显示现有章节名称。
- 上一章/下一章控制保持独立且有明确禁用态。

### 平板端（761–1024px）

- 保留右侧罗盘，但使用更紧凑的宽度、间距和标签最大宽度。
- 标签不能覆盖主要阅读列；必要时只在 hover/focus 时出现，并在触控环境下不依赖 hover。
- 触控目标仍至少为 44px，避免把平板当作“缩小桌面”处理。

### 移动端（不大于 760px）

- 罗盘变为底部浮动阅读 dock，宽度不超过视口减去左右边距。
- 使用 `max()` 与 `env(safe-area-inset-bottom)`，覆盖 iOS Home Indicator、Android 手势导航和浏览器底部工具栏变化。
- 左侧为百分比/返回顶部，中间为当前章节，右侧为 `01/02/03` 与上一/下一章。
- 章节编号保持 44px 触控面积；章节名称通过当前章节区域提供，不要求用户点中很小的文字。
- 340px 及以下只压缩非核心文字区域，不隐藏章节跳转能力，也不产生横向溢出。
- 罗盘存在时为页脚增加安全底部空间，避免最后一段内容被 dock 遮挡。

## 跨系统与设备适配

- 使用 `dvh`/安全区相关 CSS 能力时提供静态回退值。
- 使用 `matchMedia` 监听断点变化，覆盖横竖屏切换、桌面窗口缩放和移动浏览器地址栏变化。
- 触控设备不依赖 hover 展示章节名称；键盘使用 `:focus-visible` 获取同等反馈。
- 高对比度或 forced-colors 环境下保留边框、焦点轮廓、编号和活动标记，不只依靠阴影或色相。
- 主题切换沿用现有语义 token，不新增独立的亮色/暗色硬编码颜色。
- 所有滚动监听使用 passive listener 和单帧调度；组件卸载时清理监听器、观察器、计时器和 pending frame。

## 无障碍与语义

- 进度控件保留 `role="progressbar"`、`aria-valuenow`、`aria-valuemin` 和 `aria-valuemax`。
- 返回顶部按钮的 `aria-label` 包含当前百分比；章节链接保留完整章节名称和 `aria-current="location"`。
- 当前章节变化可以被 `aria-live="polite"` 感知，但滚动中的百分比不逐帧播报，避免屏幕阅读器噪音。
- 罗盘收起时继续使用 `aria-hidden` 与 `inert` 保证不可见控件不进入焦点顺序；获得焦点后必须先恢复可见再保持焦点。
- 所有按钮、链接、禁用状态和主题下的焦点轮廓均满足现有交互规范。

## 测试与验收

### 单元测试

- 测试进度在无滚动范围、负值、超出范围和正常滚动范围内的边界。
- 测试章节活动判定在多个可见章节和章节缺失时的稳定结果。
- 测试移动端滚动状态的顶部、向下、向上、停顿、焦点和 viewport 切换转换。

### E2E 与视觉检查

- 在 320、360、390、414、768、820、1024、1280 和 1440px 检查无横向溢出、主体不被遮挡和触控尺寸。
- 覆盖 Chromium、Firefox、WebKit、移动 Chromium；验证亮色、暗色和 reduced-motion。
- 验证章节点击、hash 定位、上一/下一章、返回顶部、快速滚动、键盘 Tab、Escape 后焦点恢复和横竖屏切换。
- 对罗盘在桌面、平板、移动端分别保存截图，检查百分比圆环、活动编号、标签、阴影和主题对比度。
- 提交前运行 `npm run lint`、`npm run typecheck`、`npm run unit`、`npm run deadcode`、`npm run build`、`npm run smoke` 和固定 2 workers 的完整 E2E；确认 GitHub Actions 与 Pages 部署使用本次 `main` 提交。

## 非目标

- 不修改任何中文或英文文案。
- 不修改页面章节 ID、外链、路由、数据内容或页面顺序。
- 不引入新的运行时依赖。
- 不手工编辑 `dist/`，不通过分支或 PR 发布版本。
